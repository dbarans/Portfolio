A* pathfinding

A custom A* on an 8-directional grid built from the scene’s physics, designed so that a search costs as much as the cells it visits — not the size of the map.

Problem

Enemies re-plan several times a second across a 200×200 dungeon full of obstacles. A naive A* allocates and clears map-sized arrays on every search, and an unreachable target — a locked room, a point inside a wall — means searching the entire map, every frame.

How it works

  1. A grid from physicsPhysics2D.OverlapCircle in every cell with a 1-element buffer — no allocations in the loop — into a flat bool[].
  2. The core8 directions, octile heuristic × 1.001 against equal-cost plateaus, no corner cutting, an own binary heap with lazy deletion.
  3. Version stampingNothing is cleared per search: each cell remembers the last search that touched it, so the cost follows the visited cells.
  4. SafeguardsRegion ids reject an unreachable target in O(1); past a 4,000-node budget the agent gets the route to the closest point and keeps walking.

In numbers

  • 4,000nodes — the hard budget for one search
  • 40,000grid cells (200×200)
  • O(1)rejecting an unreachable target (comparing region ids)
  • 0.25 / 0.75 sre-plan interval / cooldown after a failed search

Checked in manual play tests: the enemy avoids obstacles, doesn’t cut corners, and a target cut off by two barrels in a corridor doesn’t freeze the game.

Full technical breakdown
  1. A grid from physics. Physics2D.OverlapCircle at the centre of every cell (no triggers, a 1-element buffer — zero allocations in the loop), written into a flat bool[] instead of Node[,].
  2. The core. 8 directions, octile heuristic × 1.001 (the tie-break removes plateaus of equal-cost nodes), no corner cutting, an own binary heap with duplicates and lazy deletion.
  3. Version stamping. Instead of clearing arrays for the whole map, every cell remembers the number of the last search — the start-up cost depends on the visited cells. Buffers are cached per grid (ConditionalWeakTable — no leak once the scene is released).
  4. Safeguards. Connected-region ids (flood fill) → an unreachable target is rejected in O(1); a budget of 4,000 nodes → the route to the closest point found is returned (the agent keeps walking); a start or target inside a wall is moved to the nearest free cell.
  5. Integration. Strategy pattern (IMovementStrategy: PathfindingMovement / SimpleDirectMovement) and narrow capability interfaces (ISP): IPathStatusProvider, IWalkabilityProbe, IMovementArrivalTolerance — the enemy doesn’t know how it moves. Re-planning every 0.25 s; after a failed route, a 0.75 s cooldown.

Worth knowing
  • The world changes: PathfindingGrid.RefreshArea(Bounds) re-samples only a slice of cells and recomputes the regions when a barrel is destroyed or moved. Without it, a smashed barrel in a doorway stayed a “wall” forever, and whatever was behind it stayed unreachable for enemies.
  • Why the flood fill is 4-directional: to agree with A*’s no-corner-cutting rule — two areas that touch only at a corner really aren’t passable.
  • One bad target mustn’t kill the frame rate: hence a separate, longer cooldown after a failure — retrying an unreachable target every frame was a sure way to tank it.
