What the code shows

  • Performance by habitNode budgets, version stamping instead of clearing arrays, adaptive ray sampling, reusable buffers — each with a reason.
  • Testable codeLogic in plain C# in its own asmdef, 48 invariant tests, repeatable measurements over 200 seeds instead of eyeballing.
  • Unity beyond componentsA custom visibility-mask pipeline (second camera, RenderTexture, HLSL shaders, blending), 2D physics, editor tools.
  • Problem → cause → fixStencil → continuous mask (sprite pop-in), the nav grid’s initialisation order, a stale grid after a barrel is destroyed.
  • Delivered as a teamA finished, built game; Git with pull requests and review.
Full tech stack
Unity 6 (6000.3.8f1)
URP 2D Renderer, Tilemap, Physics2D (Raycast, OverlapCircle, Linecast, ContactFilter2D), ScriptableObject (generator settings), asmdef, [ExecuteAlways], [ContextMenu], Gizmos/Handles, EditorWindow.
Rendering / shaders
Custom HLSL shaders (URP 2D), a second camera → RenderTexture as a global texture, BlendOp Max, MaterialPropertyBlock, screen-space sampling.
C# (.NET Standard 2.1)
Logic without MonoBehaviour, events/delegates (Built), ConditionalWeakTable, MethodImpl(AggressiveInlining), reusable buffers.
Algorithms & data structures
A* (binary heap, tie-break, node budget), Kruskal’s MST + Union-Find, Hopcroft–Tarjan articulation points (iterative), graph bridges, flood fill/BFS, cellular automaton (caves), recursive shadowcasting, xorshift128, FNV-1a.
Patterns & principles
Strategy, ISP (narrow capability interfaces), Observer, generate-and-test, logic separated from the engine, configuration in ScriptableObjects.
Quality & process
Unity Test Framework (NUnit, edit mode, 48 tests), a custom editor tool, Git/GitHub (dev branch, pull requests with review), Trello.

Team project (4 people). I only show the systems I wrote myself.
